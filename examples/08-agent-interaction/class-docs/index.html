Overview

From markdown specs to a deployed agent and real user apps.

This documentation site is meant to be both a classroom handout and a live presentation. Each page focuses on one stage, the core idea behind it, and the minimum commands needed to run it.

6 stages Local to cloud Desktop and mobile

Big Idea

The same agent keeps evolving

Stage 1

Define the agent in markdown files: instructions, task, memory, tools, and evaluation.

Stage 2

Turn those files into a runnable backend that builds prompts and calls a model.

Stage 3

Wrap the runtime in a real interactive app with CopilotKit.

Stage 4

Make the agent proactive with background runs and Slack delivery.

Stage 5

Deploy the same idea to Cloudflare Workers with D1-backed state.

Stage 6

Build final user-facing apps on top of the deployed backend.

Architecture

What the final shape looks like

Markdown contract
-> Python runtime
-> CopilotKit runtime
-> Background agent
-> Cloudflare Worker + D1
-> Desktop React app
-> React Native app
By the end, the backend intelligence lives in one place and many frontends can talk to it.

Teaching Flow

Suggested classroom order

1. Contract first Show that the agent starts as readable product intent, not code.
2. Runtime second Show how the markdown becomes a real prompt and response flow.
3. UI third Show interaction, streaming, and product shape.
4. Cloud and apps last Show how the same core logic scales into a deployed product.

Class Question

What should students remember?

  • Good specs make agents easier to build and regenerate.
  • The same backend can power multiple interfaces.
  • You can move from local experiment to cloud product gradually.
  • Agents are not only chatbots; they can become proactive services.
