APIs

An API is
a contract

A server's promise: send me this request, and I'll answer with that data. You don't see its code; you only see the contract.

Where

A URL per resource: /pokemon/25, /favorites.

What

A verb that says what to do with it: read, create, change, delete.

How

A data format both sides agree on — almost always JSON.

HTTP verbs

Nouns in the URL,
verbs in the method

GET

Read.
GET /favorites
No body. Safe to repeat.

POST

Create.
POST /favorites
Body: the new item. Repeat = duplicates.

PUT

Replace.
PUT /favorites/7
Body: the whole item.

PATCH

Change part.
PATCH /favorites/7
Body: only the fields that change.

DELETE

Remove.
DELETE /favorites/7
No body.

REST in one line: the URL names the thing, the verb says what to do with it. Not /getFavorites or /deleteFavorite?id=7.
Status codes

Read the first
digit

2xx · OK

200 ok · 201 created · 204 done, nothing to return

3xx · Elsewhere

301 moved · 304 not modified, use your cache

4xx · Your fault

400 bad request · 401 who are you? · 403 not allowed · 404 not found

5xx · Server's fault

500 it broke · 503 overloaded or down

When an agent says “it works”, check the Network tab: a page can look fine while every request returns 4xx.
Calling an API

fetch, with
a verb

// read
const res = await fetch("/api/favorites");
if (!res.ok) throw new Error(res.status);
const favorites = await res.json();
// create
await fetch("/api/favorites", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ pokemon: 25 }),
});
Same pattern from the terminal: curl -X POST -H "Content-Type: application/json" -d '{"pokemon":25}' …/api/favorites

Where your
data lives

A database stores, queries and updates data so it survives refreshes, devices and users.

SQL

Four verbs
cover most of it

SELECT * FROM pokemon WHERE type = 'fire';
INSERT INTO favourites (pokemon_id) VALUES (25);
UPDATE favourites SET note = 'best' WHERE id = 1;
DELETE FROM favourites WHERE id = 1;

SQL or NoSQL

Pick by the
shape of your data

SQL

  • Tables with relationships
  • Users, orders, favourites
  • Strict, consistent

NoSQL

  • Documents, flexible shape
  • Content, logs, settings
  • Easy to change

Supabase

A database
in minutes

const { data } = await supabase
  .from('favourites')
  .select('*');

supabase.channel('favs')
  .on('postgres_changes', { event: '*',
      schema: 'public' }, render)
  .subscribe();

Postgres, an API, auth and realtime updates — without running a server.
