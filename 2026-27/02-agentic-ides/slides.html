The idea

An agent is a
model in a loop

  1. ReadYour files, your instructions, the error on screen.
  2. PlanDecides the next step towards the goal.
  3. ActEdits files, runs commands, calls tools.
  4. ObserveReads the result and loops again — until done or stuck.
Autocomplete suggests a line. Chat answers a question. An agent changes your project.
Two ways to work

Vibe coding vs
agentic engineering

Vibe coding

  • Prompt, accept, repeat
  • Fast for a throwaway prototype
  • Breaks when the project grows
  • You can't explain the result

Agentic engineering

  • You own the spec, the review and the checks
  • The agent types; you decide
  • Small steps you can verify
  • You can defend every line
“Vibe coding raises the floor. Agentic engineering raises the ceiling.”

Context engineering

Output follows
context

The agent only knows what you give it. AGENTS.md sits at the root of the repo and tells every agent what this project is and how to work in it.

Keep it short and true. Delete what's stale — wrong context is worse than none.

Skills

Teach it a
workflow once

A skill is a folder with a SKILL.md: a name, when to use it, and the steps. The agent loads it only when the task matches.

  • Review my CSS against the course rules
  • Deploy to GitHub Pages
  • Write a spec from my notes
---
name: css-review
description: Review CSS for the course
  rules. Use when asked to review styles.
---
1. List every colour and spacing value.
2. Flag values that aren't variables.
3. Check contrast and focus states.
4. Report; don't edit.

The method

Plan → spec →
build → verify

  1. PlanPlan mode. Ask the agent to explain its approach before it edits anything.
  2. SpecGoal, user, constraints, acceptance criteria, edge cases.
  3. BuildOne small change at a time. One change, one commit.
  4. VerifyRead the diff, run it, test it, look at it in the browser. Reject and rework.
Reuses: 2025-26 §4 · Workflow · Augmented Engineering deck
Verify

Review every
change

  • Does it do what the spec says — and nothing else?
  • Can I explain every line?
  • Did it add files, packages or config I didn't ask for?
  • Does it run, pass the tests, look right in the browser?

Judgement

When not to
use an agent

Learning it

The first time you meet a concept, write it yourself. Ask the agent to explain, not to do.

Can't check it

If you can't verify the result, you can't accept it.

Secrets & people

Keys, personal data, someone else's system: you decide, by hand.

In a 2026 study, students who delegated code generation understood far less than those who coded by hand — those who used AI to ask questions did well.
Cost, privacy, security

What leaves
your machine

Cost

Free tiers run out. Credits, limits and why long sessions are expensive.

Privacy

Your code goes to a provider. Never paste secrets; use .env and .gitignore.

Prompt injection

Web pages, issues and tool output can carry instructions. Approve actions; don't auto-accept everything.
