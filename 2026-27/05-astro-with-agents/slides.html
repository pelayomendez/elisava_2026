Why Astro

Zero JavaScript
by default

Fast

Pages are HTML unless a part needs interactivity.

Familiar

HTML, CSS and JS you already know, split into components.

Agent-friendly

Clear file conventions agents follow well.

Components

Code on top,
HTML below

---
// runs on the server
interface Props { name: string }
const { name } = Astro.props;
---
<article class="card">
  <h3>{name}</h3>
</article>

Read before you build: you should be able to explain any component the agent writes.

pages

    └── [id].astro     → /pokemon/25

Spec first

before the prompt

Goal

One sentence.

User

Who, and what they know.

Constraints

Stack, design, limits.

Criteria

How we know it's done.

Edge cases

What could go wrong.

Build in steps

One feature,
one commit

  1. GalleryList from the PokéAPI.
  2. DetailA page per Pokémon.
  3. PaginationNext / previous pages.
  4. FiltersType, generation…
Plan → build → verify for each step. Never all four in one prompt.
